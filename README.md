# こども市役所

高齢者やデジタル操作が苦手な人が、大きなボタンを押して話すだけで、ごみ出しの「次にやる一手」を確認できる音声Webアプリです。

このREADMEは、GitHub上の開発仕様書とNotionへ取り込むプロジェクト資料を兼ねます。標準Markdownの見出し、表、箇条書きだけを使用しています。

## 1. プロジェクト概要

| 項目 | 内容 |
| --- | --- |
| プロダクト名 | こども市役所 |
| 初期ユースケース | ごみ出し支援 |
| 主な利用者 | 一人で操作する高齢者、デジタル操作が苦手な人 |
| 提供価値 | 一回の通信で、次にやる一手が分かる |
| UIコンセプト | トランシーバー |
| 案内役 | 小さな「こども職員」 |
| 回答形式 | 音声と短い文字 |
| デモ地域 | 埼玉県富士見市・鶴瀬西 |
| リポジトリ | GitHub Public Repository。秘密値・実利用者データは保存しない |
| フロント／API | Cloudflare Workers |
| OpenAI Sites | 使用しない。既存モックは廃止・削除対象 |

## 3. MVPの目的

MVPでは、利用者がごみ出しに関する困りごとを音声で伝え、迷わず次の行動へ移れる状態を作ります。

成功条件は、詳しい制度説明を網羅することではありません。短いやり取りで、利用者が「次に何をすればよいか」を理解できることです。

## 4. MVPで扱う相談

- 今日は何ごみか
- これは何ごみか
- 出し方や分別方法
- 出し忘れたときの対応

## 5. MVPで扱わないこと

- 全国すべての自治体への対応
- 法的・行政的な最終判断
- 未確認情報をLLMだけで推測した分別回答
- 家族や市役所への自動電話
- LINE Bot連携
- 個人PCを推論サーバーとして使うこと
- OpenAI Sitesを本番ホスティングとして使うこと

## 6. 利用者と事前登録情報

### 利用者

- 一人で操作する高齢者
- スマートフォンやWeb操作が苦手な人
- 文字入力より音声入力の方が使いやすい人

### 家族が事前登録する情報

- 自治体
- 地区

MVPでは番地、氏名、電話番号などの詳細な個人情報を必須にしません。

## 7. 基本ユーザーフロー

1. 利用者が大きなボタンを押す。
2. 画面が「きいています」に変わる。
3. 利用者がごみについて話す。
4. 利用者がもう一度ボタンを押す。
5. 画面が「通信中」に変わり、無線のザーザー音を再生する。
6. 音声認識結果をごみ分別マスターと照合する。
7. 必要な場合だけLLMが一つの確認質問を作る。
8. 「こども職員」が短い文字と音声で回答する。
9. 利用者が次にやる一手を実行する。

## 8. UI／UX仕様

### 設計原則

- 主要操作は大きなボタン一つに集約する。
- 一画面に表示する情報を絞る。
- 現在の状態を文字、色、動き、音で重複して伝える。
- 高齢者を子ども扱いせず、安心感のある簡潔な表現を使う。
- 誤操作しても元に戻れるようにする。
- 音声が出なかった場合に「もう一度聞く」ボタンを必ず表示する。
- 音声だけに依存せず、同じ内容を短い文字でも表示する。

### UI状態

| 状態 | 表示 | 主な操作 |
| --- | --- | --- |
| 待機 | いつでもどうぞ | ボタンを押して録音開始 |
| 録音中 | きいています | もう一度押して送信 |
| 通信中 | 市役所に通信しています | 操作を一時的に無効化 |
| 回答 | こども職員からです | 回答を聞く、もう一度聞く、続けて話す |
| エラー | やさしい復旧案内 | 再試行または例文ボタン |

### 音の仕様

- 録音開始時は短く明確な開始音を使う。
- 通信中は小さな無線ノイズをループ再生する。
- 回答開始前に無線がつながったことを示す短い音を使う。
- 自動再生に失敗した場合は、即座に再生ボタンへ切り替える。
- 音量が大きすぎるノイズや長い効果音は使わない。

## 9. こども職員のペルソナ

こども職員は、幼い印象を持ちながらも、情報の裏付けを持つ市役所の案内役です。

### 話し方

- 孫くらいの親しみやすさ
- やさしく、短く、素直な日本語
- 2文程度を基本とする
- 最初に結論、その後に次の行動を伝える
- 絵文字、長い箇条書き、専門用語は使わない
- 高齢者を見下す表現や過度な幼児語は使わない

### 回答例

「乾電池は燃やすごみじゃなくて、有害ごみだよ。ほかのごみに混ぜず、有害ごみの日に出してね。」

### 分からない場合

分別を推測せず、品物名、材質、大きさ、電池の有無から必要なことを一つだけ聞きます。

## 10. 回答ロジック

回答は次の優先順位で決定します。

1. 危険物ルール
2. 自治体の確認済みごみ分別マスター
3. 収集日・地区ルール
4. LLMによる確認質問
5. 安全なフォールバック

LLMは、確認済みマスターにない品目のごみ区分を断定しません。主な役割は入力の言い換え、意図分類、確認質問、短い回答への整形です。

## 11. 危険物の安全ルール

- 乾電池、ボタン電池、充電池、モバイルバッテリーを燃やすごみへ案内しない。
- 膨張、破損、発熱した電池は通常回収へ案内しない。
- スプレー缶、カセットボンベ、ライターは中身の状態を確認する。
- 刃物や割れ物は包み方と危険表示を案内する。
- 公式資料で確認できない場合は、市の担当窓口への確認を案内する。

## 12. ごみデータ仕様

### マスター項目

| フィールド | 内容 |
| --- | --- |
| `id` | 安定したルール識別子 |
| `aliases` | 音声認識の揺れを含む品目名 |
| `category` | ごみ区分 |
| `answer` | 利用者向けの短い回答 |
| `danger` | 危険物フラグ |
| `source` | 根拠資料名 |
| `sourceUrl` | 根拠となる公式URL |
| `verifiedAt` | 最終確認日 |
| `area` | 適用自治体・地区 |

### データ運用

- 回答で使用する分別ルールには公式の根拠URLと確認日を必須にする。
- 自治体資料の改訂時に差分確認を行う。
- 危険物ルールは通常品目より優先してテストする。
- 収集曜日が未確認の場合は断定しない。
- デモデータと本番確認済みデータを明確に分ける。

## 13. 音声入力仕様

| 項目 | 採用方針 |
| --- | --- |
| 録音 | Browser MediaRecorder API |
| マイク取得 | `getUserMedia` |
| ノイズ対策 | echo cancellation、noise suppression、auto gain control |
| 音声認識 | Cloudflare Workers AIのWhisper Large V3 Turbo |
| 言語 | 日本語を明示 |
| 語彙補助 | 地名、ごみ区分、品目名を初期プロンプトへ追加 |
| 最大サイズ | 12 MBを初期上限とする |

音声認識に失敗した場合は「読み取れませんでした」だけで終わらせず、マイク位置、話す速さ、再試行方法を短く案内します。

## 14. 音声出力仕様

| 項目 | 採用方針 |
| --- | --- |
| TTSエンジン | AivisSpeech Engine |
| 実行場所 | Google Cloud Run GPU |
| 声の方向性 | かわいく、高めで、若い女性または子どもに近い声 |
| 初期候補 | AIVMX「まお」。試聴とライセンス確認後に固定 |
| 出力 | WAVまたはブラウザ再生に適した音声 |
| ブラウザ内蔵TTS | 障害時のフォールバックのみ |

### 読み間違い対策

- 画面表示用の `displayText` と読み上げ用の `speechText` を分離する。
- 固有名詞、ごみ区分、地区名を読み辞書で管理する。
- 数字、単位、曜日、略称を読み上げ前に正規化する。
- よく使う回答は音声と読みを回帰テストする。
- 読み辞書を変更した場合はレビュー対象にする。

## 16. API仕様

### `POST /api/transcribe`

音声を日本語テキストへ変換します。

入力：`multipart/form-data` の `audio`

成功レスポンス：

```json
{
  "text": "乾電池は何ごみですか"
}
```

### `POST /api/chat`

ごみマスターを照合し、回答または確認質問を返します。

入力：

```json
{
  "message": "乾電池は何ごみですか"
}
```

成功レスポンス：

```json
{
  "displayText": "乾電池は燃やすごみじゃなくて、有害ごみだよ。",
  "speechText": "かんでんちは、もやすごみじゃなくて、ゆうがいごみだよ。",
  "source": "master",
  "ruleId": "dry-battery",
  "category": "有害ごみ"
}
```

### `POST /api/speech`

読み上げ用テキストから音声を生成します。ブラウザからAivisSpeech Engineへ直接接続せず、Cloudflare Workerが認証と入力検証を行います。

入力：

```json
{
  "speechText": "かんでんちは、ゆうがいごみだよ。"
}
```

成功時は音声データを返します。

## 17. セキュリティとプライバシー

### 基本方針

- 個人PCをサーバーやCIランナーとして使わない。
- ブラウザからクラウド推論基盤へ直接アクセスさせない。
- APIキーや秘密情報をフロントエンドへ含めない。
- 音声データを永続保存しない。
- 本番ログへ生音声や発話全文を残さない。
- 地域情報は自治体・地区までを標準とする。
- すべての外部通信をHTTPSに限定する。
- TTSサービスはWorkerからの認証済みリクエストだけを受け付ける。

### 公開リポジトリのルール

- 実利用者の氏名、住所、電話番号、音声、相談内容をコミットしない。
- テストには架空データまたは自治体の公開情報だけを使用する。
- `.env.example` には変数名とダミー値だけを記載する。
- 鍵、トークン、サービスアカウントJSON、ローカルDB、Terraform stateをコミットしない。
- 脆弱性情報は公開IssueではなくGitHubのPrivate vulnerability reportingを使用する。
- Pull Request由来のコードへ配備用Secretsを渡さない。

### 認証情報

| 用途 | 方針 |
| --- | --- |
| ChatGPTからCloudflare操作 | Cloudflare MCPプラグイン／コネクタ認証。キーをチャットへ貼らない |
| WorkerからWorkers AI | Workers AI binding。実行時APIキー不要 |
| GitHubからCloudflare配備 | GitHub Actions Secretsがそろっている場合だけWranglerを実行 |
| GitHubからGCP配備 | GitHub OIDCとWorkload Identity Federation。JSONキー不要 |
| WorkerからTTS | 専用シークレットを自動生成し、Cloudflare SecretsとGCP Secret Managerへ保存 |

### Cloudflareの操作方法

- 通常の設定確認や手動操作はCloudflare MCPを優先する。
- ブラウザ操作は、初回ログイン、OAuth承認、MCPに公開されていない設定だけに限定する。
- GitHub Actionsからの自動配備は、MCPの認証を引き継がず、GitHub Actions Secretsを使用する。
- Cloudflare用シークレットがない状態を正常な「CIのみ」モードとして扱う。

## 18. CI/CD仕様

### Pull Request CI

Pull Requestごとに次を実行します。

1. 依存関係の固定インストール
2. TypeScript型検査
3. ESLint
4. 単体テスト
5. ごみマスターのスキーマ検証
6. 危険物ルールの回帰テスト
7. 読み辞書と `speechText` のスナップショットテスト
8. Cloudflare Workerのビルド
9. TTSコンテナのビルド
10. 依存関係とコンテナの脆弱性検査

Pull Requestから本番環境へはデプロイしません。

### ステージング

- `main` へのマージ時、Cloudflare用シークレットがそろっている場合だけステージングWorkerを配備する。
- シークレットがない場合はCI成功のままCloudflare配備をスキップする。
- TTS変更時はコンテナをイメージダイジェストでArtifact Registryへ保存する。
- GitHub OIDCでGoogle Cloudへ認証し、Cloud RunのステージングRevisionを更新する。
- API疎通、音声形式、代表的な分別質問をスモークテストする。
- ステージングTTSは最小インスタンス数を0にする。

### 本番

- Gitタグまたは手動リリースを起点にする。
- GitHub Environmentの承認後に開始する。
- ステージングで検証した同一成果物を再ビルドせず昇格する。
- TTSを先に更新し、ヘルスチェック成功後にWorkerを更新する。
- 本番TTSは音声待ち時間を抑えるため最小インスタンス数を1にする。
- デプロイ後に代表質問と音声生成のスモークテストを行う。

### ロールバック

- Cloudflare Workerは直前のDeploymentへ戻す。
- Cloud Runは直前のRevisionへトラフィックを戻す。
- データ変更は後方互換を保ち、アプリと独立して戻せるようにする。

## 19. テスト方針

### 必須テスト

- 「乾電池」を燃やすごみへ案内しない。

- CloudflareとGCPが必要とする実行時シークレット

## 26. Notionへの取り込み

### Markdownファイルとして取り込む場合

### コピー＆ペーストする場合

READMEの本文をすべてコピーして、空のNotionページへ貼り付けます。見出し、表、箇条書き、コードブロックがそのままブロックへ変換されます。

### Notionで別ページへ分ける推奨単位

- プロダクト仕様：1〜11章
- 技術仕様：12〜17章
- CI/CD・運用：18〜23章
- 意思決定・バックログ：24〜25章
